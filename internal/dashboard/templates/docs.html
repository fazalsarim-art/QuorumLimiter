API examples

Replace the placeholder key and use a fresh Idempotency-Key for each new logical request.

Make a decision

curl -i {{.Data.BaseURL}}/v1/decisions \
  -H 'Authorization: Bearer qlk_YOURPREFIX_your-secret' \
  -H 'Idempotency-Key: 01JEXAMPLE00000000000000000' \
  -H 'Content-Type: application/json' \
  --data '{"policy_id":"password_reset","subject":"customer_4821","cost":1}'

Response codes

  • 200 — allowed; body includes remaining_milli and reset info.
  • 429 — denied by the token bucket; retry after Retry-After seconds.
  • 401 — missing, invalid, or revoked API key.
  • 404 — policy not found or inactive.
  • 409 — same Idempotency-Key reused with different content.
  • 422 — invalid policy id, subject, cost, or idempotency key.
  • 503 — no leader or quorum; retry.
  • 504 — timed out awaiting commit; retry with the same Idempotency-Key.
